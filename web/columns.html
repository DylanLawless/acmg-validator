TSV column guide

One row describes one ACMG criterion for one variant. A variant normally has 28 rows with the same item_id; information shared by those rows must match. The beginner template starts with the four essential fields, followed by variant identification, evidence, QEM outcomes and review details.

Start with the TSV template or eight-variant example. Edit the source file and reimport it to validate changes. A blank cell does not prove that a check was negative or completed. See the ACMG criteria and QEM outcome guide when choosing values.

Column names and meanings

Required fields are needed for a valid record; conditional fields become necessary for specific assessments or exports; recommended fields improve interpretation and traceability; optional fields may be omitted; and generated fields are filled from the rule catalogue or existing data. The four TSV headers that must be present are item_id, criterion, status and evidence_status. A present header is different from a valid value: each populated row still needs an allowed status and evidence state.

The beginner template puts essential fields first. The full TSV export also includes generated rule IDs and preservation fields. Column names, rather than their order, determine how files are imported. For each variant, supply either hgvs_c or coordinate; gene is recommended but not mandatory. Missing fields remain missing, not negative evidence. The tool checks that a location is supplied but does not verify its HGVS syntax or reference sequence. On narrow screens, scroll the table horizontally.

ColumnRequirementMeaning
Essential fields
item_idRequiredUnique ID for a variant review. Repeat it across the criterion rows for that variant.
criterionRequiredACMG criterion on this row (for example, PVS1). Use one of the 28 defined codes.
statusRequiredACMG disposition: not_assessed, accepted, rejected, not_applicable or needs_second_review.
evidence_statusRequiredEvidence state: not_assessed, present, absent_after_review, not_available, not_applicable, conflicting, insufficient_quality or requires_second_review.
Variant identification
coordinateConditionalGenomic location, e.g. chr17:43124027. Supply this or hgvs_c. Record the reference build and alleles where relevant to make the variant unambiguous.
hgvs_cConditionalCoding DNA HGVS description, e.g. c.68_69del. Supply this or coordinate; identify the reference transcript when known.
geneRecommendedGene symbol, such as BRCA1, if known. May be blank when the variant is identified by its location.
transcriptRecommendedReference transcript accession associated with the HGVS description, e.g. NM_007294.4.
genome_buildRecommendedReference genome assembly for genomic coordinates, e.g. GRCh38.
hgvs_pOptionalProtein-level HGVS description, if applicable and known.
Evidence and interpretation
applied_strengthGeneratedStrength for this criterion; the catalogue default is supplied when omitted. May be supporting, moderate, strong, very_strong or standalone, subject to criterion restrictions.
source_refConditionalTraceable ACMG evidence source; required when verified is TRUE. Separate from qem_source_ref.
notesConditionalJustification required for certain accepted criteria or when changing the default evidence strength.
verifiedOptionalTRUE or FALSE, default FALSE. TRUE requires a source and a signed-off, named reviewer.
classificationOptionalEntered overall interpretation: pathogenic, likely_pathogenic, vus, likely_benign or benign; may be blank.
QEM evaluation
qem_raw_outcomeOptionalResult of the negative question: TRUE → 0 confirmed invalidation; FALSE → 1 no invalidation and verified qualifying evidence; NA → 0 not conclusively evaluated (default).
qem_source_refConditionalTraceable source for the QEM rule evaluation; required for conclusive TRUE/FALSE outcomes or when qem_verified is TRUE.
qem_verifiedConditionalTRUE is required for a conclusive QEM TRUE/FALSE; otherwise defaults to FALSE. A named, signed-off review is also required.
qem_rule_idGeneratedNegative QEM rule identifier generated from the criterion and current catalogue. Do not type or rename it in the beginner template.
Review and clinical context
reviewerConditionalReviewer name or identifier; required when ACMG evidence is verified or a QEM outcome is conclusive.
review_dateRecommendedDate of review in YYYY-MM-DD form; missing dates produce a warning.
signoffConditionalTRUE for a signed-off review; otherwise FALSE (the TSV importer defaults to FALSE if omitted). Required to be TRUE for verified claims.
guideline_basisRecommendedGuideline version or relevant ClinGen expert-panel specification used in the review; missing values produce a warning.
diseaseOptionalDisease or condition being investigated.
inheritanceOptionalInheritance model considered, e.g. AD or AR.
Advanced exchange fields
record_jsonOptionalMachine-readable variant-level metadata for lossless TSV round-trips; not intended for routine editing.
criterion_jsonConditionalPreserves criterion-level details such as mandatory caveat confirmations. For criteria requiring caveats, use canonical JSON or supply this field with the confirmed caveats.

Errors prevent validated exports. Warnings identify information that still needs review but can be retained. QEM exports use the installed versioned rule catalogue, recorded in the bundle metadata. Check rule meanings before importing a TSV created with another release. Structural validity does not establish that every evidence check is complete.

Structured records

Canonical JSON is the complete exchange format, including additional fields and caveats. Spreadsheet TSV makes the common fields easy to inspect, but not every nested detail fits into a cell. If an export includes record_json or criterion_json, change the visible columns for ordinary edits; the importer checks that shared values agree and does not use embedded metadata to silently restore a cleared visible field.
